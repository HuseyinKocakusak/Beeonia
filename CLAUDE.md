# Working rules for this repository

## Design changes: mockups first

Before writing or changing any code for a visual design change, check whether the user has already chosen a direction from mockups.

A visual design change is any of these:
- a new page or a redesign of an existing page
- a new section, or a new layout for an existing section
- a new visual style (colours, typography, spacing system, components) applied across the site

If the user has not chosen a mockup in this conversation:
1. Do not touch the repository yet: no edits, no branches, no commits.
2. Remind the user, in the language they wrote in, that the agreed rule is to see 2 to 3 static mockups first. In Turkish: "Önce 2-3 statik mockup görüp birini seçmemiz gerekiyordu. Kodlamaya geçmeden önce mockupları hazırlayayım mı?"
3. Offer to make 2 to 3 static mockups as an artifact, with no repository changes, and wait for the user's choice.

Proceed without mockups only if the user explicitly says to skip them, or points to a mockup they already approved.

These do not need mockups: text and translation changes, fixing a bug or an alignment problem, adjusting the size or colour of a single element, adding or editing literature articles, and other small tweaks inside an existing design.
